## TODO — Q&A Forum V1

> **Context:** Q&A Forum is School-Hive's first feature in the School-Hive sequence (Q&A → Scholar Stories → Mentorship → SOP Lab → Country Hive). It replaces ephemeral Facebook/WhatsApp scholarship advice with permanent, searchable, credentialed pages. Full spec at `School-Hive/docs/Q&A_system.md`. This TODO covers **V1 only** — the 8 launch-critical items from spec Section 9. Phase 2/3 are explicitly deferred until real usage data exists; do not scaffold them.

> **Scope — V1 (8 items):** (1) Structured question posting — title, body (markdown), category, tags, context fields, language (1.1–1.2). (2) Duplicate-detection search panel at compose time (1.3). (3) Answering + Accept + upvote + reason-tagged downvote (1.4–1.5). (4) Lightweight identity verification / Verified badge (5.3). (5) Full-text search + category/tag/country/level browse and filters (1.7, 4.1–4.2) with mobile/low-bandwidth constraint (4.4). (6) Basic points + starter badges, not full privilege ladder (2.1, 2.3). (7) QAPage schema.org markup (4.3). (8) Founding-cohort seeding plan — ops checklist, not code (5.1–5.2).

> **Key patterns to reuse (do not reinvent):** Auth — `src/Hooks/useAxiosSecure.jsx` + `src/Hooks/useRole.jsx` on client, `verifyToken` + role-guard middleware on server (`Schole-hive-server`). - [x] **Q6 — Daily rep cap number for V1** — Spec says “capped early on” mirroring SO, but number is a starting point. Propose 20/day for new/low-trust accounts; tune after usage data. Decide inline in Task 4/10. **Resolved:** 50/day, not 20. A single accepted + upvoted + sourced answer already totals 15+10+3 = 28 points — a 20 cap would throttle a new contributor's very first great answer, exactly the founding-cohort moment (spec 5.2) this system should reward, not cap. 50 covers a strong day's contribution while still blocking low-effort or self-vote farming. Starting number only, per the spec's own appendix note — revisit once real usage data exists.
- [x] **Q7 — Source-link +3 timing** — Immediate on submit vs after review? Immediate is simpler V1; review adds safety. Decide inline in Task 4. **Resolved:** Immediate on submit, no review gate — matches the "simple V1, harden later" pattern used elsewhere in the spec. The existing reason-tagged `unsourced`/`incorrect` downvote (1.5) already acts as a post-hoc safety net for a bad or fake source, so a separate review queue isn't needed just to guard a 3-point bonus.
- [x] **Q8 — Language behavior** — Body can be code-switched (Banglish/Hinglish) as typed per 1.1; structured fields (category/tags/country) stay language-independent for search (1.7). Confirm UI labeling inline in Task 5. **Resolved:** Selector copy: English · বাংলা (Bengali) · हिन्दी (Hindi) · Mixed (Banglish/Hinglish). Native script for Bengali/Hindi, and "Banglish/Hinglish" instead of the technical term "code-switched," so the selector reads as an invitation ("type however you normally text") rather than a formal classification. V1 ships a manual pill-selector defaulting to the UI's own locale — no auto-detection; that's a reasonable Phase 2 addition, not a V1 requirement.
- [x] **Q9 — Which corridor to launch first (5.1)** — Market-research question; validate against current FB-group activity. Decide inline in Task 13, not a code decision. **Resolved:** Bangladesh → Canada, provisional. Raw UNESCO headcount still has the US and UK slightly ahead of Canada (2023: US ~8,500, UK ~6,600, Canada ~5,800), but multiple 2025 industry sources name Canada the current top-preferred destination for Bangladeshi students, driven by visa-approval rates, the post-graduation work permit, and PR pathways. That policy volatility is itself the case for Canada as a launch corridor: it's the fast-changing, rule-sensitive environment School-Hive's freshness mechanism (3.2) exists for. Bangladesh's outbound-study volume overall has also tripled over 15 years (16,609 → 49,151 students, 2008 → 2022) — a growing market to seed into, not a flat one. Named, organized Bangladesh-Canada student communities already exist (campus associations, diaspora groups) — a recruitable founding-cohort pool per 5.2. **Caveat:** this is a destination-volume/trend proxy, not actual Facebook-group activity data — private-group post volume isn't visible to web search, so it doesn't fully clear the spec's own validation bar (Appendix). Before public launch, manually check post-frequency in 2–3 named Bangladesh↔Canada groups (and optionally one alternate corridor, e.g. India→Germany) to confirm.
